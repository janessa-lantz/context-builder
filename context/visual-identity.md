# Visual Identity

The brand's observable design facts, one section per element. This is the visual counterpart
to the [messaging canon](messaging-canon.md): the canon is what the company says, the visual
identity is what the company looks like. [Skills](../skills/) read both, so every generated
asset looks like the company, not just sounds like it.

The same source rule as the canon applies. The LLM records only what is observable on live
published surfaces (extracted by the [visual-identity job](../builder/jobs/visual-identity.md)),
with each entry attributed to where it was observed. A human may override or augment any entry
with decisions the live site cannot show (print rules, admired references, internal
conventions); those entries are marked `source: human`, and the LLM never overwrites them on
a re-run.

---

## logo

*(primary mark, wordmark variant, clear-space and minimum-size rules, file locations)*


## colors

*(hex values with usage notes. primary, secondary, accent, neutrals: text / muted / background.
Note observed proportions: most B2B sites run roughly 60% neutral, 30% primary, 10% accent,
with the accent reserved for CTAs and highlights.)*


## typography

*(display and heading face, body face, code or data face if used. Weights and the observed
scale.)*


## style

*(the observed visual language: illustration vs. photography vs. geometric, iconography style,
chart and data-viz conventions, image treatment per content category where the blog shows a
consistent pattern.)*


## avoid

*(visual patterns the brand does not use. Usually `source: human`: the live site shows what is
present, a human states what is off-limits.)*


## admired-references

*(brands whose visual work anchors the aspiration, each with what specifically about it.
Always `source: human`; aspiration is never observable.)*


## usage-notes

*(rules for applying the identity in generated assets: accent restraint, contrast minimums for
text on color, logo handling. Seeded by the job from observed practice, refined by humans.)*
